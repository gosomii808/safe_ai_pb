# AI Report 개발 결과 전달 요청서

팀원 Claude에게 아래 내용을 그대로 전달해 주세요. 목표는 Claude가 만든 코드를 현재 SafePB AI 프로젝트 구조에 잘 맞게 전달하고, 이후 Codex가 변경사항을 바로 적용/검증할 수 있게 만드는 것입니다.

---

아래 저장소 구조와 `docs/ai-report_claude_handoff.md`를 기준으로 `ai-report` 기능을 개발해 주세요.

결과를 전달할 때는 다음 형식으로 주세요.

## 1. 변경한 파일 목록

- 새로 만든 파일
- 수정한 파일
- 삭제한 파일이 있다면 이유

## 2. 적용 순서

- 어떤 파일을 먼저 붙여 넣거나 교체해야 하는지
- 기존 파일 전체 교체인지, 일부 diff 적용인지 명확히 표시

## 3. 코드 전달 방식

- 가능하면 unified diff 형식으로 주세요.
- diff가 어렵다면 파일별 전체 코드로 주세요.
- 파일 경로는 저장소 기준 상대 경로로 적어 주세요.
  - 예: `frontend/app/(dashboard)/ai-report/page.tsx`

## 4. API 계약

- 새로 추가한 백엔드 엔드포인트
- request query/body
- response 타입
- 프론트에서 호출하는 함수명
- 필요한 환경변수

## 5. 데이터/DB 변경

- Prisma schema 변경 여부
- migration 필요 여부
- seed 또는 테스트 데이터 필요 여부
- 기존 `backend/dev.db`에서 바로 동작하는지

## 6. 로컬 실행/검증 결과

- 실행한 명령어
- 성공/실패 여부
- 남아 있는 에러나 TODO

## 7. 주의사항

- 아직 더미로 남겨둔 값이 있다면 위치와 이유
- `userId` 임시 처리 방식
- 민감정보 복호화/익명화 처리 방식

## 중요 지침

- 기존 대시보드 레이아웃, `NEXT_PUBLIC_API_BASE_URL`, `frontend/lib/api.ts` 패턴을 최대한 유지해 주세요.
- `ai-report/page.tsx`만 단독으로 예쁘게 만드는 것보다, 현재 Nest/Prisma 구조에 맞게 연결되는 것이 우선입니다.
- 한글 깨진 문구는 정상 UTF-8 한글로 교체해 주세요.
- 전체 파일을 주는 경우에도 어느 파일을 완전 교체해야 하는지 명확히 표시해 주세요.
- 마지막에 Claude가 이해한 구현 요약과 남은 TODO를 짧게 남겨 주세요.

## 가장 좋은 전달물 형식

가장 좋은 전달물은 아래 두 가지입니다.

1. `patch.diff`
   - 저장소 루트 기준 unified diff
   - Codex가 바로 적용할 수 있는 형식

2. `handoff.md`
   - 변경 요약
   - 적용 순서
   - API 계약
   - DB/migration 여부
   - 테스트 결과
   - 남은 TODO

이렇게 전달하면 Codex가 이후 변경사항을 바로 적용하고 타입 체크/빌드 검증까지 이어갈 수 있습니다.
